# Election data schema

Each supported state has one file at `public/data/<state>.json` (lowercase postal code, e.g. `tx.json`).
Files are **generated by scripts in `scripts/`** from official sources. Don't hand-edit them; fix the script and re-run it.

## File shape

```jsonc
{
  "schemaVersion": 1,
  "state": "TX",
  "stateName": "Texas",
  "election": {
    "id": "53815",                       // source system's election ID
    "name": "2026 November General Election",
    "date": "2026-11-03",
    "type": "general"                    // general | primary | runoff | special
  },
  "generatedAt": "2026-10-16T18:00:00.000Z",
  "sources": [
    { "name": "Texas Secretary of State – Candidate Information", "url": "https://..." }
  ],
  "races": [ /* Race */ ]
}
```

## Race

| Field | Type | Notes |
|---|---|---|
| `id` | string | Stable slug, unique within the file, e.g. `us-house-7`, `county-harris-sheriff` |
| `office` | string | Display name, e.g. `U.S. Representative, District 7` |
| `level` | `"federal" \| "state" \| "county"` | Government level |
| `category` | string | Used to group races and match addresses. One of `us_senate`, `us_house`, `statewide`, `state_senate`, `state_house`, `state_board`, `judicial`, `county` |
| `district` | string \| null | District number or name for districted races (`"7"`, `"15th Court of Appeals"`), otherwise `null` |
| `county` | string \| null | Title-case county name **without** "County" for county races (`"Fort Bend"`), otherwise `null` |
| `unexpiredTerm` | boolean | `true` for special or unexpired-term seats |
| `candidates` | Candidate[] | Ordered as on the ballot (party order, then write-ins) |

## Candidate

| Field | Type | Notes |
|---|---|---|
| `name` | string | Display name (title case) |
| `ballotName` | string | Exactly as filed and printed on the ballot |
| `party` | string | Short code: `R`, `D`, `L`, `G`, `I` (independent), `W` (write-in), `O` (other) |
| `partyName` | string | `Republican`, `Democratic`, `Libertarian`, `Green`, `Independent`, `Write-in`, … |
| `incumbent` | boolean | Currently holds this office and is running for it again |
| `writeIn` | boolean | Declared write-in candidate |
| `website` | string \| null | Campaign website as filed, normalized to `https://` (null if missing or invalid) |
| `fecId` | string \| null | Verified FEC candidate ID for federal candidates (including write-ins); null when unmatched/ambiguous and for non-federal candidates. Resolved at build time from OpenFEC by office, state, House district, and normalized name; party breaks ties. Sourced overrides live in `scripts/data/fec-overrides.json`. |
| `occupation` | string \| null | As filed |

### Privacy

Candidate emails and mailing addresses appear in some source data, but **we don't publish them**. Only fields listed above make it into the generated files.

## Rules

- **Neutrality:** never reorder candidates by anything but official ballot order, and never drop a qualified candidate (including third-party and write-in candidates).
- **Traceability:** every file lists its `sources`, and `generatedAt` is shown in the UI.
- **Open seats:** if no candidate has `incumbent: true`, the race is an open seat. We don't hardcode current officeholders.

## FEC enrichment

`npm run data:tx` queries OpenFEC once per office/state with pagination (`per_page=100`). Set `FEC_API_KEY` in the build environment for a free api.data.gov key, or use the default, rate-limited `DEMO_KEY`. Never commit a key. API errors abort generation without overwriting the data file; unresolved identities are logged and stored as null. The UI links only resolved IDs, using the election date year as the cycle. Run `node --test scripts/lib/*.test.mjs` to check matching and URL normalization.
